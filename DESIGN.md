Архитектура и алгоритмы игры «Быки и коровы»

1. Структуры данных и алгоритмы

Состояние игры

В src/index.ts состояние игры хранится в отдельных переменных:

secret — строка с загаданной комбинацией;

attempts — количество сделанных попыток;

isGameOver — флаг завершения игры;

currentLength — выбранная длина комбинации;

currentBase — выбранная система счисления.

Для хранения состояния используются примитивные типы string, number и boolean. Это позволяет явно разделить данные игры и упростить управление её состоянием.

История попыток отображается в упорядоченном HTML-списке <ol>. Каждая новая попытка добавляется в виде отдельного элемента <li>. Такой подход сохраняет порядок попыток и позволяет наглядно отображать результаты.

Структуры данных в игровой логике

В проекте используются следующие структуры:

String — для хранения загаданной комбинации и пользовательского ввода.

Array — для работы с отдельными цифрами комбинаций и последовательностью доступных цифр.

Set — в isValidGuess для проверки уникальности цифр.

Map — в countPossibleSecrets для мемоизации результатов вычислений.

Алгоритм evaluateGuess

Файл: src/core/evaluateGuess.ts.

Функция принимает загаданную комбинацию и пользовательский вариант.

Алгоритм работы:

Обе строки приводятся к нижнему регистру, чтобы сравнение было нечувствительным к регистру.

Строки преобразуются в массивы символов.

С помощью reduce выполняется проход по загаданной комбинации.

Если символы находятся на одинаковых позициях, увеличивается счётчик быков.

Если символ присутствует в пользовательском варианте, но находится на другой позиции, увеличивается счётчик коров.

Функция возвращает объект с количеством быков и коров.

Использование reduce позволяет получить оба результата за один проход по массиву загаданной комбинации.

Алгоритм countPossibleSecrets

Файл: src/core/countPossibleSecrets.ts.

Функция вычисляет количество возможных комбинаций заданной длины без повторения цифр.

Используется рекурсивный алгоритм с мемоизацией.

Принцип вычисления основан на количестве доступных вариантов для каждой следующей позиции:

для первой позиции доступно base цифр;

для второй — base - 1;

для третьей — base - 2;

далее количество вариантов последовательно уменьшается.

Таким образом, количество комбинаций определяется произведением:

base * (base - 1) * ... * (base - length + 1)

Алгоритм предусматривает два базовых случая:

если длина комбинации превышает основание системы счисления, возвращается 0;

если длина равна 0, возвращается 1.

Для повторных вычислений используется Map, в котором сохраняются результаты по ключу, состоящему из длины и основания системы счисления.

2. Сложность алгоритмов (Big O)

Обозначения:

n — длина комбинации;

b — основание системы счисления.

generateSecret — O(n × b)

Файл: src/core/generateSecret.ts.

Сначала создаётся массив доступных цифр размером b. Затем в цикле выбирается случайная цифра, удаляется из массива с помощью splice и добавляется в загаданную комбинацию.

Одна операция splice в худшем случае требует O(b), поскольку после удаления элемента оставшиеся элементы массива могут сдвигаться.

Цикл выполняется n раз.

Итоговая временная сложность — O(n × b).

Дополнительная память — O(b), поскольку хранится массив доступных цифр и результирующая комбинация.

evaluateGuess — O(n²)

Файл: src/core/evaluateGuess.ts.

Преобразование строк в массивы занимает O(n).

Затем выполняется reduce, который проходит по всем n символам. Внутри прохода для поиска символа используется includes, требующий в худшем случае O(n).

Поэтому общая временная сложность составляет O(n × n), то есть O(n²).

Дополнительная память — O(n) для массивов символов.

isValidGuess — O(n)

Файл: src/core/isValidGuess.ts.

Функция проверяет длину комбинации, преобразует символы в нижний регистр, создаёт Set для проверки уникальности цифр и проверяет допустимость каждого символа с помощью every.

Каждая из этих операций требует линейного времени относительно длины комбинации.

Итоговая временная сложность — O(n).

Дополнительная память — O(n) для массива символов и множества уникальных символов.

countPossibleSecrets — O(n)

Файл: src/core/countPossibleSecrets.ts.

Функция использует рекурсию, в которой на каждом шаге длина и основание уменьшаются на единицу. На каждом шаге выполняется только один рекурсивный вызов, поэтому дерево рекурсии не разрастается.

Без учёта уже сохранённых результатов выполняется не более n рекурсивных шагов.

Мемоизация позволяет повторно использовать ранее вычисленные значения и не выполнять повторные вычисления для одинаковых параметров.

Итоговая временная сложность одного нового вычисления — O(n).

Дополнительная память — O(n) для стека рекурсии и сохранения промежуточных результатов в Map.

3. Принципы Clean Code

Разделение ответственности (Single Responsibility Principle)

Каждая функция игровой логики выполняет отдельную задачу:

generateSecret отвечает за генерацию комбинации;

evaluateGuess — за подсчёт быков и коров;

isValidGuess — за проверку пользовательского ввода;

createDigitValidator — за проверку допустимости отдельной цифры;

countPossibleSecrets — за подсчёт возможных комбинаций.

Это упрощает тестирование, поддержку и изменение отдельных частей проекта.

Понятные имена переменных и функций

В проекте используются имена, отражающие назначение элементов:

generateSecret;

evaluateGuess;

isValidGuess;

countPossibleSecrets;

currentLength;

currentBase;

isGameOver.

Благодаря этому назначение функций и переменных понятно без дополнительных комментариев.

Ранний возврат (Early Return)

В src/core/isValidGuess.ts проверки выполняются последовательно. Если длина комбинации неправильная или обнаружены недопустимые символы, функция сразу возвращает false.

Это позволяет не выполнять лишние проверки и уменьшает вложенность условий.

Переиспользование кода (DRY)

Функция createDigitValidator используется для проверки допустимости цифр в разных частях приложения:

в isValidGuess при проверке всей комбинации;

в src/index.ts при обработке пользовательского ввода.

Таким образом, правило проверки цифр не дублируется в нескольких местах.

Тестируемость и внедрение зависимости

В src/core/generateSecret.ts функция принимает генератор случайных чисел через параметр random, по умолчанию использующий Math.random.

Это позволяет передавать управляемую функцию случайных чисел в тестах и проверять генерацию комбинаций с предсказуемым результатом.

Типизация

В проекте используется TypeScript. Для параметров и возвращаемых значений функций заданы типы.

Например, evaluateGuess возвращает объект с числовыми свойствами bulls и cows. Это помогает обнаруживать ошибки типов ещё на этапе разработки.

Разделение игровой логики и интерфейса

Основные алгоритмы находятся в каталоге src/core, а работа с DOM и обработка пользовательских событий сосредоточены в src/index.ts.

Такое разделение позволяет изменять интерфейс игры, не переписывая основные алгоритмы.
